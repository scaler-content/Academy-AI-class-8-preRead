Building Agents in n8n: Tools, Memory and Human Approval

Turn the agent loop into practical workflows, then add controls before it takes action

Class 8AI and AgentsPre-Read

1. Welcome

In Class 7, you explored how an agent decides what to do and uses tools. In this session, that same loop moves into n8n’s AI Agent node. You’ll build a read-only assistant, connect tools and memory, deliberately test failure cases, and then create a second workflow that can act only after a person approves the action.

What to keep in mindThis pre-read introduces the ideas and vocabulary you will use in class. The hands-on build and detailed demonstrations happen during the session.

As you read, think about what an agent should be allowed to do, what information it needs, and where a person should remain in control.

2. From the canvas to the AI Agent node

In earlier workflow-building classes, you drew each step and branch yourself. The AI Agent node places the agent loop inside one node. It connects a chat model, system instructions, tools, memory, and a maximum-iteration setting.

Chat model

The model that chooses the next step or tool call.

System message

The instructions that define the agent’s role and behaviour.

Max iterations

A limit that helps prevent an agent from looping indefinitely.

Keep in mindThe model makes the decisions; the surrounding workflow and settings provide the structure and controls.

3. Workflow 1: Day-Trip Buddy

The first workflow builds a travel-planning assistant. It begins with a chat trigger and a model, then gains tools to find a city, check weather, and retrieve information. The agent can chain tool calls when a question requires more than one source.

Chat Trigger

Receives the user's message and starts the workflow.

find_city

Turns a city name into coordinates.

get_weather

Retrieves a forecast using coordinates.

Wikipedia

Provides information about a place.

Keep in mindTool names and descriptions matter. The model uses them to decide which tool is relevant; the order of calls is not necessarily written as a fixed sequence in the workflow.

4. Give it memory

Memory lets the agent use information shared earlier in the same conversation. The class adds Simple Memory so the agent can retain context per session rather than treating every message as unrelated.

Without memory

A later message may not contain details supplied earlier.

With Simple Memory

The agent can use earlier conversation context associated with the session.

Keep in mindMemory is not the same as a permanent knowledge base. Think about what context should persist and for how long.

5. Break it on purpose, then fix it

The class tests failure cases such as missing context, repeated tool problems, and an agent that keeps iterating. It introduces Max Iterations as a stopping control and Retry On Fail for recovering from a flaky tool.

Max Iterations

Stops an agent after a configured number of steps.

Retry On Fail

Retries a node when a failure may be temporary.

Keep in mindA retry is useful for a temporary failure, not for every error. A missing or invalid input will usually remain invalid when repeated.

6. Workflow 2: an agent that acts, with a human gate

The second workflow moves from read-only assistance to an external action. A support-desk agent prepares a customer message, but a human approval step pauses the workflow before the message is sent.

Prepare

The agent drafts or proposes the action.

Approve or decline

A person reviews the proposed action.

Execute

The external action happens only after approval.

Keep in mindThe approval gate is a control boundary: the agent can prepare an action, but it does not get to send it automatically.

7. Change one thing and export

Learners make a small change to a workflow, test the behaviour, and export the result. This reinforces that workflow changes should be checked rather than assumed to work.

Keep in mindMake a small change, test the behaviour, and export the finished workflow.

8. A Few Terms to Know

These terms will help you follow the explanations and activities in the session.

AI Agent nodeThe n8n node that runs the agent loop, connecting a chat model with instructions, tools, memory, and a maximum-iteration setting.
Tool descriptionText that tells the model what a connected tool does and when it should be used.
Simple MemoryThe n8n memory option used in the class to retain conversation context per session.
Human approval gateA checkpoint that pauses an action until a person approves or declines it.
What you’ll walk away withYou’ll be able to assemble an AI Agent workflow in n8n, connect tools and memory, use iteration limits and retries to handle failures, and place a human approval gate before an agent performs an external action.
